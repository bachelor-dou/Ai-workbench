### 项目定位与用途

本项目是一个面向Claude Code的插件及独立的npm库，核心功能是将传统的上下文压缩摘要机制替换为基于Jev决策的精准压缩方案。它通过快速请求对对话中的每一次工具调用及其返回结果进行独立评分，根据评分结果决定保留、截断或丢弃。被保留的内容保持原始文本不变，旨在为AI编程助手提供高效且无损的会话上下文管理工具。

### 解决的问题

传统上下文压缩依赖大语言模型生成摘要，该过程具有信息丢失风险，关键细节如文件路径、精确报错、约束条件或执行命令可能在摘要中消失，影响后续任务执行。本项目彻底摒弃重写机制，仅依据Jev的决策移除不再需要的工具调用与结果，确保用户与助手的原始文本按序完整保留，从根本上解决了压缩过程中的关键信息丢失痛点。

### 使用场景

主要面向使用Claude Code进行复杂代码开发、调试与重构的开发者及AI辅助编程工作流。适用于会话长度持续增长、需要频繁压缩历史上下文以控制Token消耗的场景。特别适合对历史工具调用结果有强依赖，且要求压缩后关键路径、错误堆栈或配置参数必须原样保留的长周期编程任务。

### 技术架构与特性

项目采用分层状态压缩架构，将完整对话状态按阶段适配至最大状态Token限制，通过逐步截断输入、精简文本与折叠旧消息控制体积。采用并发请求机制，将评分问题拆分至单次请求限制内并行处理，并基于阈值策略执行保留、截断或移除决策。内置无分词器Token估算模型，支持插件与库双形态部署，失败时抛出异常交由调用方处理。

它主要解决免费模型来源分散、接口不统一、频繁限流以及配额管理困难的问题。项目会在某个提供方受限时自动切换到下一个，并跟踪每个 key 的使用量，帮助用户尽量不超出各家免费额度；同时密钥加密存储，降低集中管理多把 key 的负担。

### 使用场景

适合个人做 LLM 试验、原型验证，以及需要兼容 OpenAI 客户端的本地或自托管接入。README 还提到可配合 CLI 和 coding agents 使用，并提供 Docker、自托管、桌面端以及 macOS、Windows、Android 下载，适合想快速试用多个免费模型的开发者。

### 技术架构与特性

核心是 OpenAI-compatible proxy 与 router 架构，对外统一提供 /v1。模型目录由签名 feed 自动更新，免费安装使用月度快照，premium 路由器可当天获取新模型；项目还强调密钥加密、自动故障切换、按 key 统计用量，以及支持自定义聊天、嵌入、图像、音频端点。

### 项目定位与用途

DeskcommCRM 是一个开源、自托管的 CRM，主打“面向 WhatsApp 的 AI 销售操作系统”。它让 AI 代理在同一套系统里完成接待、资格筛选和销售，并强调可部署在自己的服务器上、数据由用户掌控，定位为 Kommo、Octadesk、Intercom 的开放替代方案。

### 解决的问题

它针对企业在 WhatsApp 上做销售与客服时，人工响应慢、线索筛选耗时、功能受限以及持续订阅成本高等痛点。项目希望把沟通、自动化和客户数据集中到自有环境中，减少对第三方平台的依赖，也避免“月费”和功能锁定。

### 使用场景
